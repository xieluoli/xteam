## 从三次独立事件升级的硬规则

暂无。不得为凑数把初始约束或同一事件重复计为三次。

升级格式：

### C-001：规则名称

- 规则：可执行、适用范围清楚的一句话。
- 原因：反复发生的根因及后果。
- 证据：关联教训 ID 与至少三次独立事件的日期、任务、测试/差异/commit。
- 检查：具体测试、静态检查或评审操作；有必要才生成独立自动化检查任务。
- 升级日期：YYYY-MM-DD。

## 升级约束

- 先合并同根因教训，再按独立事件计数；同一天也可有不同任务的独立事件，但必须各自有证据。
- 与既有规则冲突或证据不足时，记入 task.md 待决策，不自行覆盖。
- 不因升级就重构全仓；检查方法的代码改动仍是单独工作项，需要明确范围和验收。

升级核验历史保存在[对应日期复盘](daily/2026-10-29/review.md)，不再追加到现行规则表。
