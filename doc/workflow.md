## 本地运行约定

- 本文、[lessons.md](lessons.md)、[code-standards.md](code-standards.md)随Git共享。调度器每次读取仓库内doc固定入口，不依赖聊天记忆或复制他人memory。
- 每台设备自行选择协调checkout，doc/路径相对该仓库；正式产品文档仍为docs/。本机worktree绝对路径只记.local/xteam-cycle/，源码命令显式指定工作目录。
- 每天北京时间 09:00 执行、21:30 复盘。三个不同的执行日期组成试跑；重试不增加天数。第三个执行日的复盘完成后暂停两条自动化，提交试跑结果，等待用户决定后续。
- 每次定时执行与夜间复盘均由独立会话承载，不在旧聊天继续。开始时按 Asia/Shanghai 当日日期设置标题为 `YYYY-MM-DD XTEAM 优化` 或 `YYYY-MM-DD XTEAM 复盘`；跨会话通过共享doc、本设备运行证据和持久worktree接续，不依赖旧聊天。未提交源码只在原设备，不从“本地开发完成”推断其他设备已可拉取。
- 每天计划 20 个最小工作项，至少一个有实际用户价值的 feat。执行前核对现状及未完成项，允许取消已满足或无法证明的问题并从候选池补位；不能为凑数编造修复或自动扩张产品范围。
- 在已批准的轻量资源空间范围内可自主选题、实现、验证和修复；无需逐项再次审批。新增依赖、执行引擎、任务会话/Token 采集、复杂任务状态、OAuth、多团队、数据库架构变化等另列待决策，不擅自实施。
- 2026-10-29 用户追加每日发布授权：当天范围内代码通过验证后，允许提交到 codex/ 日期分支、推送、创建 PR、等待 CI 并合入 main，通过 SSH root@p.space01.cc 更新既有独立实例，取得 https://xteam.space01.cc 的功能截图。此授权覆盖每日试跑的发布闭环；不含新增依赖、执行引擎、删除数据卷、强推、重置用户改动、改密钥/账号或真实付费模型调用。备份与验收使用现有授权通道，不修改无关生产业务数据。晚间同时复盘 commit 与未提交变更，无 commit 如实记录。
- 在专用持久化 worktree 工作，保留未提交成果供用户审阅；不直接在主 checkout 实施业务改动。复用已记录路径；首次按需用应用管理工具创建，基础为当前已核对的本地 main，不自动拉取或重置。不得因未提交改动就丢弃或重复执行。
- 使用 `.local/xteam-cycle/` 保存运行记录、差异、测试输出和共享锁；不记录密钥或完整业务正文。执行与复盘共用一把锁，运行前记录拥有者和时间，活跃或无法确认的锁不抢占。异常残留先核对拥有者是否结束。
- 本机锁以原子创建取得，记录主机/拥有者/时间，try/finally只释放自己的锁；它不提供跨设备互斥。多设备先核对远端task认领和平台备注，同一任务有人进行先协调，结束前fetch并合并他人进度，不强推或整文件覆盖。步骤见[跨设备接续](handoff.md)。
- 任务状态：待做 / 进行中 / 待验证 / 已完成 / 阻塞 / 已取消。每项先写计划与验证条件，再改代码；预计超过 3 个文件时先写分段小任务。
- 行为变更先有失败回归用例。迭代运行相关测试，日终运行 pnpm test、pnpm build；涉及网页交互再运行 pnpm test:e2e。环境问题不冒充产品缺陷，也不冒充验证通过。
- 已有依赖可按锁文件安装；不修改清单/锁文件以绕过安装问题，不使用生产环境代测。遵守当前 AGENTS.md 与本地硬规则。
- 纯文档改动验证差异、相对链接、敏感信息和干净checkout接续，明确未重跑产品测试；不触发VPS部署。共享的历史.local路径只是原设备证据索引，无法读取就写未复验，不假称已拿到历史证据。
