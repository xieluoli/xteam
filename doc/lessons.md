# XTEAM 错题本

本文件只记录实际发生的独立事件，采用「规则 + 原因 + 证据」。同一故障的重试、多个失败断言、跨日复述不重复计数。没有新教训允许记录“无新增”。

相同根因归入同一教训ID；本表维护规则、原因、独立事件累计数和证据索引，更新原条目，不按运行追加流水。新增事件细节/返工写[对应日期review](daily/README.md)，再回填本表的计数和日期证据链接。同一故障重试或跨日复述不增加计数。第三次独立且证据齐全、范围清楚、无冲突时才升级到[code-standards.md](code-standards.md)并关联编号；不足或冲突留待决策。

证据优先：回归测试与输出、commit、差异快照、用户纠正。敏感正文与凭据不进入证据记录。

本文件随Git共享；历史日志/截图路径是原设备私有证据索引，不随仓库上传。其他设备先核对相关代码/PR，需要重新验证时记录本设备结果，不把无法访问的历史证据当成亲自复验。

## L-001：把连接故障与密钥认证故障分开排查

- 规则：远端连接失败时，先确认失败发生在网络、SSH 握手还是密钥认证阶段，再决定修复路径；不因 fetch 失败就断言没有配置密钥。
- 原因：本机已加载有效密钥，但直连在认证前关闭；通过现有本地代理后认证成功，重新生成密钥不能解决该网络问题。
- 证据：2026-10-29 本会话用户指出“应该配了 ssh 密钥”；ssh-add -l 确认已加载；直连 kex_exchange_identification 失败；使用 Clash 127.0.0.1:7897 的临时 ProxyCommand 后 GitHub 认证成功并 fetch 到 b8eae9f98。没有更改全局代理或 SSH 配置。
- 独立事件：2026-10-29 / 环境同步；计数 1。
- 状态：观察中，未升级。

## L-003：即时反馈不能用最终一致断言代替

- 规则：验证错误发生当下不应出现的旧成功反馈时，等待错误可见后检查即时 DOM；不能等待旧提示自行超时消失。
- 原因：Playwright 自动重试断言会一直等待，旧提示两秒后自然消失也能让缺陷代码通过测试。

- 状态：观察中，未升级。

## L-006：重建容器要保留完整网络成员

- 规则：部署前检查 .NetworkSettings.Networks 的全部连接和服务别名，重建时恢复反代实际使用的网络；不能只复制 .HostConfig.NetworkMode。
- 原因：旧 XTEAM 容器的默认模式是 bridge，但还连接了 Caddy 所在 xteam_default；第一次重建遗漏第二网络，本地端口可访问而公网反代无法解析服务名。
- 证据：2026-10-29 release-deploy.log 记录公网 502 和自动回退；release-rollback-diagnosis.log 中 Caddy 为 lookup xteam-rewrite no such host，旧容器有 bridge/xteam_default 而失败容器只有 bridge；release-deploy-retry.log 补齐网络后公网版本匹配，资源数量保持一致。

- 状态：观察中，未升级三次硬规则；下轮部署先读取本教训和 task.md 接续要点。

## L-013：容器内备份路径必须使用挂载后的容器路径

- 规则：部署脚本同时记录宿主数据目录与容器挂载目录；在容器内执行 SQLite 在线备份时使用容器路径，完成后再从宿主挂载目录移动到受限备份目录。
- 原因：首次部署把宿主路径 `/opt/xteam-rewrite/data/...` 直接传给容器内 SQLite 进程，容器内目录不存在，备份在生产切换前停止。
- 证据：2026-10-30 / PR #11 部署；`vps-deploy.log` 记录首次备份失败，`vps-backup-diagnosis.log` 确认宿主与容器路径差异，改用 `/data/.backup-*` 后 `vps-deploy-retry.log` 记录 `integrity_check=ok`、权限 600，并完成精确 SHA 部署。
- 独立事件：2026-10-30 / 日常优化部署备份路径；计数 1。
- 状态：观察中，未升级。
