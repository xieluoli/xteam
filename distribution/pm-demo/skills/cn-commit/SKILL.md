执行 git 提交时严格遵守下列铁律（通用提交约定，以目标仓已确认规范为准）。

## 提交信息
- **用中文**写提交信息。
- 每个改动点单独一行，标注文件操作类型 + 路径：`[A] 新增 path` / `[M] 修改 path` / `[D] 删除 path` / `[R] 重命名 path` / `[C] 复制 path`。
- 说明**为什么**改（产品/需求动机），不只罗列「做了什么」。

## 执行
1. 先 `git status` + `git diff`（或 `git diff --staged`）核对实际改动，逐项能追溯到用户需求。
2. 沿用目标仓已确认的提交身份；未配置时请用户确认，**不**改全局 git config：
   ```
   git commit -m "<中文信息>"
   ```
3. 署名与协作尾注遵循目标仓已确认的规范，不继承原作者的个人设置。
4. **不自动 push**，除非用户明确要求。
5. 当前在默认分支且改动较大时，提交前先确认是否要开分支。

## 信息模板
```
<一句话概括本次提交的目的/为什么>

[M] 修改 path/a —— 改动点与原因
[A] 新增 path/b —— 为什么需要
```
